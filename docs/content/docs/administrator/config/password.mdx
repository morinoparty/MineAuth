## config.json Example

```json5
{
  "password": {
    "pepper": "3q2-7wZ0bJx9N1pQyH4sVtK8mR6cLfA5eUoD2gIiW0M",
    "memory": 19456,
    "iterations": 2,
    "parallelism": 1,
    "hashLength": 32,
    "saltLength": 64
  }
}
```

## Password Configuration

| Key | Type | Required | Description |
|-----|------|----------|-------------|
| `pepper` | string | No | Secret value appended to player passwords before hashing with Argon2id. Generated automatically when omitted |
| `memory` | number | No | Argon2id memory cost in KiB. Default is `19456`, the OWASP minimum recommendation |
| `iterations` | number | No | Argon2id iteration count. Default is `2` |
| `parallelism` | number | No | Argon2id parallelism. Default is `1` |
| `hashLength` | number | No | Hash length in bytes. Default is `32` |
| `saltLength` | number | No | Random salt length in bytes. Default is `64` |

When `pepper` is not set, MineAuth generates a random 32-byte value at startup and saves it to `config.json`.

Changing `pepper` invalidates every existing player password, so players must run `/ma change` to issue a new one. Keep this value secret and include `config.json` in your backups.

The Argon2id parameters are stored in each hash, so changing them does not break existing passwords. Each player's password is re-hashed with the new parameters on their next successful login.

### Migration from Older Versions

Passwords hashed by versions before 0.4.0 are not accepted. Players must run `/ma change` to issue a new password.

When the pepper is generated, `config.json` is rewritten. The original file is saved as `config.json.bak` because unknown keys and formatting are not preserved.
